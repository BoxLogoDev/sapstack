## Pillar A — "증명한다": 진단 품질 eval 하니스 ⭐

> 갭 G4 · gstack qa/canary/devex-boomerang 대응 · ETHOS ①Ground-truth ②Evidence 를 측정 가능화

### 파일
- `data/eval/gold-set.yaml` — 대표 증상 30~50건. 케이스 = `{id, symptom, env(ECC/S4), module, expected:{root_cause, tcodes[], check_points[], sap_note?}}`. symptom-index 90·sap-notes 112 에서 ground-truth 명확한 것만 선별.
- `data/eval/README.md` — gold-set 스키마 + 기여 가이드.
- `schemas/eval-gold-set.schema.json` — gold-set 구조 검증.
- `mcp/eval/run.ts` — 케이스 → 해당 에이전트 시스템프롬프트로 답변 생성(Anthropic API, 로컬).
- `mcp/eval/judge.ts` — LLM-judge: 기대 진단 대비 채점(정확/부분/오답 + T-code 누락 감지 + ETHOS 위반).
- `scripts/eval-diagnosis.sh` — 오케스트레이터(`--dry-run`, `--case ID`, `--module`, `--all`). API 키 없으면 dry-run 만.
- `scripts/check-eval-goldset.sh` — **API 불필요** 정합성 게이트(스키마·중복·참조 무결성). CI 편입 가능.
- `docs/eval/methodology.md` — 채점 기준·한계.
- `docs/eval/REPORT.md` — baseline accuracy 누적.

### Acceptance
- `bash scripts/eval-diagnosis.sh --dry-run` → gold-set 로드 + 케이스 수·모듈 분포 출력(API 불필요).
- `bash scripts/check-eval-goldset.sh` 통과(스키마·중복·tcode 참조 무결성).
- `ANTHROPIC_API_KEY` 있을 때 1 케이스 실측 채점 동작 → REPORT.md baseline 기록.
- 정적 게이트 14종 회귀 없음.
