# CVI JP: 일본 (Japan) 로컬라이제이션

> 초안. 세율·법정 기한은 공개 제도만 적고, 확인되지 않은 숫자는 **확인 필요**로 남긴다.
> 한국 가이드를 번역하지 않는다.

## 개요

| 항목 | 값 |
|------|-----|
| **CVI 코드** | JP |
| **SAP 활성화** | SFW5 Country Version JP (확인 필요: 사이트별 스위치명) |
| **회계기준** | J-GAAP 및/또는 IFRS (상장사). 병행 공시 여부는 회사 정책 |
| **회계연도** | 관례 4월 1일 ~ 3월 31일. 1~12월도 가능 |
| **기본 통화** | JPY (엔, 소수점 없음) |
| **소비세** | 표준 10%, 경감 8% (식품·정기 구독 신문 등 — 2019-10 시행) |
| **전자장부** | 전자장부보존법 (전장법) |
| **인보이스** | 적격청구서등보존방식 (インボイス制度, 2023-10-01 시행) |
| **급여** | 관례 월 1회.  Exact 지급일은 회사 취업규칙 |

## 1. 회계 기준 & 폐쇄

### 1.1 회계연도 설정
- 일본 상장사·대기업은 **4월 시작**이 흔하다. SAP Fiscal Year Variant 는 사이트마다 다름.
- T-code: **OB29** (Fiscal Year Variant) — 변형 코드 자체는 하드코딩하지 말 것.
- 결산 마감 일정(주주총회·유가증권보고서)은 회사·거래소 규칙. **확인 필요**.

### 1.2 J-GAAP vs IFRS
| 항목 | J-GAAP | IFRS |
|------|--------|------|
| **대상** | 비상장·일부 상장 | 임의 적용 또는 특정 공시 |
| **재고** | 원가법 중심 | 원가와 순실현가능가치 중 낮은 금액 등 |
| **SAP** | Document type·평가 영역은 회사 차트에 따름 | 동일. 계정과목표는 하드코딩 금지 |

**확인 필요**: 감가상각 방법의 법정 강제 여부, 자산 세무상 내용연수 표.

## 2. 세무 규정

### 2.1 소비세 (消費税, Consumption Tax)
공개된 국세청 제도 (2019-10 이후):

| 구분 | 세율 | 비고 |
|------|------|------|
| 표준 | 10% | 대부분의 재화·용역 |
| 경감 | 8% | 음식품(외식·주류 제외), 정기 구독 신문 |
| 면세/비과세 | — | 대상 범위는 국세청 안내. 확인 필요 |

SAP:
- T-code: **FTXP** 세금코드. 코드 값(V1/V2 등)은 회사 설정. 스텁의 V1=10% / V2=8% 는 **예시일 뿐**.
- 세금절차 이름 `TAXJP` 는 기존 스텁에 있었음. 사이트 실명 **확인 필요**.

### 2.2 적격청구서등보존방식 (インボイス制度)
- 2023-10-01 시행. 매입세액 공제에 **등록번호가 있는 적격청구서**가 필요.
- 발행사업자 등록번호 체계·공제 경과조치는 국세청 안내가 수시 갱신. **경과세율·시기 확인 필요**.
- SAP: 벤더/고객 마스터에 등록번호 필드, 출력(NACE) 서식. 구체 필드명은 릴리스별 **확인 필요**.

### 2.3 인지세 (印紙税)
- 계약서 종류·금액 구간별로 세액이 다름. 표를 여기서 재작성하지 않는다. **확인 필요**.

### 2.4 법인세·신고
- 신고 기한은 사업연도 종료일 + 원칙 2개월, 연장은 세무서 승인. 정확한 일자는 회사마다 다름. **확인 필요**.
- e-Tax 전자 신고는 국세청 경로. SAP 직접 전송은 커스텀/벤더 솔루션인 경우가 많음.

## 3. 전자장부보존법 (電子帳簿保存法)

### 3.1 개요
- 전자거래 데이터는 종이 출력 보존이 아니라 **전자 그대로** 보존하는 쪽이 본규칙.
- 2022-01 개정으로 전자거래의 전자 보존이 강화됐다. 유예·경과 조치는 연도마다 바뀌므로 **현재 적용 여부 확인 필요**.

### 3.2 요구 요지 (제도 취지, 세액 아님)
- 진실성(타임스탬프·상호 관련성 또는 정당한 사무처리 규정)
- 가시성(화면·프린터로 출력 가능)
- 검색(거래일·거래금액·거래처 등)

### 3.3 SAP 대응
- 전표·출력물·IDoc/PDF 를 위 검색 요건으로 아카이브하는지가 핵심.
- T-code 예: **FB03** (전표 조회), 출력 이력. 전장법 전용 T-code는 표준이 아님.
- 보관 연한: 법인세법상 장부 7년이 흔히 인용됨. 업종·세목별로 다를 수 있어 **확인 필요**.

## 4. 급여 & 사회보험

일본 사회보험은 다음 네 축이 기본이다. **요율은 연도·도도부현·건강조합마다 다르므로 적지 않는다.**

1. 후생연금
2. 건강보험 (협회켄포 또는 조합)
3. 고용보험
4. 노재보험 (노동재해)

SAP HCM: 국가 그룹(MOLGA) JP, 임금유형·공제 스키마는 회사  spl. **요율 하드코딩 금지.**
T-code: **PA30**, **PC00_M99** (국제 드라이버 — 일본 전용 리포트명은 확인 필요).

연차: 노동기준법상 근속연수별 부여. 일수 표는 여기에 재수록하지 않는다. **확인 필요**.

## 5. 은행 & 결제

### 5.1 Zengin
- 전국은행협회 **전은(全銀) 포맷**이 국내 이체의 사실상 표준.
- SAP: **DMEE** / Payment Medium. 트리 이름은 하우스뱅크마다 다름.

### 5.2 확인 필요
- 전은 EDI 최신 레코드 길이·문자코드 (EBCDIC vs UTF-8 이행)
- 덴사이넷(전자기록채권) 연동 여부

## 6. SAP 특수 사항

- Country Version JP 활성화 후 세금절차·주소 형식·은행 키가 일본용으로 열린다.
- 회계연도 변형: 기존 스텁은 K1(4~3), K2(1~12)를 예시로 씀. **회사 변형을 하드코딩하지 말 것.**
- Document type 예시(SA/DR/KR)는 표준 관례일 뿐 사이트 설정이 우선.
- ECC vs S/4: 고객/벤더는 S/4 에서 **BP**. 세금계산서 출력은 NACE vs BRF+ Output Management.

## 7. SAP 체크리스트 (월/분기/연)

### 월별
- [ ] F110 / DMEE 전은 파일 테스트 런 후 실전송
- [ ] OB52 기간 — 사용자가 준 회사코드만
- [ ] 소비세 세금코드 변경 여부 (FTXP) — 경감 대상 자재

### 분기별
- [ ] 소비세 확정신고 자료 (e-Tax). 마감일은 과세기간에 따라 **확인 필요**
- [ ] 적격청구서 등록번호 누락 벤더 점검 (XK03 / BP)

### 연간
- [ ] 전장법 검색·타임스탬프 점검
- [ ] 회계연도 변형(4월 시작) 특별기간 13–16 사용 여부
- [ ] 사회보험 요율 개정 반영 — 요율 값은 관보/협회 안내. 저장소에 박지 않음

## 9. 자주 묻는 질문 (FAQ)

**Q. 한국 부가세 10% 설정을 그대로 쓰나요?**
A. 안 됩니다. 일본은 소비세 10/8 과 적격청구서 등록번호가 핵심입니다.

**Q. 회계연도를 1월로 바꿔도 되나요?**
A. 제도상 가능. SAP OB29 변형과 세무 신고 달력을 같이 맞춰야 합니다.

**Q. 전장법 때문에 ArchiveLink 가 필수인가요?**
A. 필수는 표준 문장으로 단정하지 않는다. 검색·진실성 요건을 충족하는 저장이면 된다. 제품 선택은 확인 필요.
