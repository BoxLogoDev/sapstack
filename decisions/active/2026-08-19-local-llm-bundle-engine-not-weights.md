# 로컬 LLM 은 엔진만 번들하고 가중치는 운영자가 반입한다

**날짜** 2026-08-19 (probe·검증 배선 마감 시점) · **범위** `apps/desktop/apps/electron/src/main/local-llm.ts`

## 배경

제조기업 폐쇄망에서 도는 것이 이 데스크톱의 전제다. 클라우드 API 를 못 쓰는 현장이 있으므로
로컬 추론이 필요한데, 모델 가중치(GGUF)는 수 GB 라 설치파일에 넣으면 배포가 불가능해진다.

## 결정

**엔진은 번들, 가중치는 미번들.**

- `llama-server`(llama.cpp CPU 빌드, ~18MB)를 설치파일에 `extraResources` 로 넣는다
- 운영자가 GGUF 를 `~/.sapstack/models/` 에 넣으면(USB 반입) 앱이 자동 감지해 기동한다
- 루프백 전용(`127.0.0.1:11435`), 모델 id 는 파일명과 무관하게 `sapstack-local` 고정
- 디렉토리에 GGUF 가 여럿이면 **파일명 알파벳순 첫 번째**를 로드

## 근거

- 설치파일이 이미 약 219MB(v2.4.0 실측)다. 4B 모델을 넣으면 2.4GB, 8B 면 4.7GB 가 더 붙는다
- 폐쇄망 반입은 어차피 USB 다 — 모델도 같은 경로로 들어온다
- 루프백은 outbound 가 아니므로 `SAPSTACK_AIRGAPPED` 차단(`main/airgap.ts:9,23`)과 충돌하지 않는다
- 모델 id 를 고정하면 운영자가 파일명을 바꿔도 설정이 깨지지 않는다

## 버린 대안

| 대안                  | 왜 안 골랐나                                                                  |
| --------------------- | ----------------------------------------------------------------------------- |
| 소형 모델을 번들      | 설치파일이 2~5배가 되고, 그 모델이 SAP 진단에 쓸 만한지 보증할 수 없다        |
| 최초 실행 시 다운로드 | 폐쇄망에서 불가능. 이 제품의 전제와 정면 충돌                                 |
| Ollama 의존           | 별도 설치를 요구하면 폐쇄망 반입 품목이 하나 더 늘고, 버전 관리 주체가 갈린다 |

## 남은 리스크 (해결 안 됨)

- **권장 모델팩 미확정**. Qwen3 4B Q4_K_M(~2.4GB)이 후보지만, 8B 는 개발 머신 실측 0.75 tok/s 라
  타깃 사양(16GB RAM 사무용 노트북)에서 쓸 만한지 **측정 전**이다. 문서는 "장비 성능에 따라 선택"
  으로만 서술하고 "권장" 단정을 피하고 있다
- **실기기 채팅 1턴 미검증** — probe IPC·온보딩 검증은 타입·정적으로만 통과

## 뒤집는 조건

- 타깃 사양에서 실측 tok/s 가 실용선에 못 미치면 → 클라우드 필수 + 폐쇄망은 별도 대응으로 후퇴
- 설치파일에 넣어도 될 만큼 작고 쓸 만한 SAP 특화 모델이 나오면 → 번들 재검토
