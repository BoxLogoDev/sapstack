# eval 채점은 LLM-judge 3표 다수결로 한다

**날짜** 2026-06-24 (v2.4.0 eval 하니스) · **범위** `scripts/eval/run.mjs`, `docs/eval/methodology.md`

## 배경

gold-set(32건/18모듈)으로 답변 품질을 자동 채점하려면 채점자가 필요한데, 채점자도 모델이다.
단일 judge 로 돌리면 **judge 자체의 분산**이 점수에 그대로 실린다 — 같은 답변을 두 번 채점해도
점수가 흔들려서, 점수가 내려갔을 때 그게 답변이 나빠진 건지 judge 가 흔들린 건지 구분할 수 없다.

## 결정

judge 를 **홀수 표(기본 3표) 다수결**로 돌리고 `score_spread` 를 함께 기록한다.
점수는 절대값이 아니라 **추세**로 읽는다.

근거 코드: `scripts/eval/run.mjs:178` — _"judge 다수결 표 수(홀수 권장). 1 이면 단일 judge(기존 동작). 분산 감소용."_
방법론: `docs/eval/methodology.md:53` "judge 다수결(분산 감소)", `:77` _"LLM-judge 의 분산 … 다수결(3표)로 크게 완화"_

## 근거

- baseline 0.585 를 기준선으로 삼으려면 측정 자체가 재현 가능해야 한다
- 3표는 분산을 줄이면서 비용이 선형이다 (5표는 이득 대비 비쌌다)
- `score_spread` 를 남기면 **"점수가 낮다"와 "judge 들이 갈렸다"를 구분**할 수 있다

## 버린 대안

| 대안                             | 왜 안 골랐나                                     |
| -------------------------------- | ------------------------------------------------ |
| 단일 judge                       | 분산이 점수에 그대로 실려 추세 판독 불가         |
| 사람 채점                        | 32건×18모듈을 매 릴리스마다 사람이 볼 수 없다    |
| 규칙 기반 채점(정답 문자열 매칭) | SAP 진단 답변은 표현이 다양해 문자열로 못 잡는다 |

## 뒤집는 조건

- gold-set 이 50건을 넘고 3표 비용이 CI 예산을 압박하면 → 표본 채점으로 전환 검토
- judge 모델이 충분히 안정돼 단일 표의 분산이 무시할 수준이 되면
